# Arreaga Painting — website and design board

A single-page marketing site for Arreaga Painting (residential and commercial painting), recreated from a Figma design, plus a **design board** for viewing and reviewing the site on Laptop and Mobile screens.

- **Live site:** https://pierregarcia1.github.io/arreaga-painting/ (GitHub Pages, public)
- **Repo:** https://github.com/pierregarcia1/arreaga-painting (full source; GitHub Pages serves the `docs/` folder)
- **Design source:** https://www.figma.com/design/pLjBaJapATm7s9KUyxKL6z/Arreaga-Painting (desktop 1440px and mobile 390px frames)

> **Before going live for real:** the header phone button dials a fictional placeholder, `tel:+15550100000`. Replace it in `index.html` in two places: the header phone button (`<a class="call">`) and the hero phone link (`<a class="phone-link">`, which also shows the number as text). The consultation form also has no backend yet. See [Known gaps](#known-gaps).

## Run it locally

The board loads the site over HTTP, so it must be served; opening `board.html` straight from disk won't work (the single-file builds in `dist/` do open from disk).

```bash
cd Paint
python -m http.server 8080
```

- Site: http://localhost:8080/index.html
- Design board: http://localhost:8080/board.html

In the Claude desktop app, a local `.claude/launch.json` entry named `paint-board` (python `http.server` on port 8080) starts the same server.

**Cache tip:** browsers cache `style.css` and `index.html` aggressively when served this way. If an edit doesn't show up, hard-refresh (Ctrl+Shift+R).

## The site

One page, thirteen blocks, in this order: header, hero (Home), About, Services, Projects, project story (cabinet concept), Process, Colour and finish guide, Common questions (FAQ), Contact banner, Request a consultation (form), Map (`#visit`), footer. Anchor ids: `home`, `about`, `services`, `projects`, `process`, `contact`, `consultation`.

### Look and feel

| | |
|---|---|
| Fonts | Work Sans (weight 900, uppercase for headings; regular for body), from Google Fonts. Inter and Barlow Condensed are still loaded as fallbacks |
| Colours | deep red `#921a12`, navy ink `#17202b`, pale blue-white `#f6fafe`, grey `#f0f4f8`, line `#d6dade`, muted text `#4a5560`, soft text `#c5ccd4` (CSS variables on `html.drl`) |
| Style | An industrial commercial look inspired by commercial-contractor sites: full-bleed photo hero under a dark overlay, heavy uppercase headings, square uppercase buttons, white shadowed cards, a navy colour guide and footer, a solid red call-to-action band, and a quote form with underlined fields. It is all scoped under `html.drl` (set on the `<html>` tag) in the last block of `style.css`. Section labels keep their small red dash and uppercase style |
| Imagery | Architectural stock images are labelled "illustrative concepts", not completed Arreaga projects |
| Icons | Arrows are inline SVG (class `ar`), not text characters, so iOS can't turn them into emoji. The menu icon and check marks are plain text characters |

### Responsive behaviour

| Width | Layout |
|---|---|
| over 1280px | Full desktop: 120px header with nav and CTA, 72px side margins |
| 1101-1280px | Compact header (smaller nav and button, 48px margins) so the nav and CTA don't crowd |
| 961-1100px | Tablet landscape: fluid columns, nothing fixed-width, form stacks under its intro |
| 801-960px | Same tablet layout, header switches to the hamburger menu |
| 601-800px | Single column with roomier gutters (portrait tablet, large phones) |
| 600px and below | Single column phone layout |

Media queries use `min-width: 800.02px` and `600.02px` on purpose: at fractional widths (zoomed or high-DPI screens) a plain `min-width: 801px` leaves a gap where neither layout applies.

### Header

- **Logo:** the logo image has a lot of empty margin, so it is shown oversized inside a clipping window as tall as the header (`html.biglogo` in `style.css`): artwork about 213px wide on desktop, 191px on tablet widths, 163px on phones, where the bar is 104px tall.
- **Desktop:** sticky, fixed 120px height (it does *not* resize on scroll; resizing caused a flicker loop and a visible sliver). A shadow appears after 60px of scrolling (removed again below 10px, a deliberate dead zone). A red indicator slides under the nav link of the section you're in (scroll-spy).
- **Hide on scroll:** the header slides away while scrolling down past 240px and returns on scroll up.
- **Mobile (960px and below):** logo centred in a 96px bar, a round phone button on the left, hamburger on the right. The menu is a compact floating card: the current section is grey with a red marker bar, hover and keyboard focus are red, and a red "Request a consultation" button closes it. It closes on link tap, outside tap or Esc.

### Motion

All implemented with `transform` and `opacity` only. Reveals are driven by scripts at the bottom of `index.html`; animated effects are skipped when the visitor has "reduce motion" on.

- Headline line reveals (each line rises from behind a mask)
- Photo wipe-in with a slow zoom settle
- Hero "fresh coat" wall wipe (a flat wall colour rolled away by a red edge, plays once)
- Staggered card and list entrances
- Button fill sweep, card hover, subtle parallax on the hero and About photos only
- Before/after slider on the cabinet story (the "before" is a washed-out copy of the same photo; swap in a real before photo when available)
- Film grain on dark sections, branded scrollbar (slim ink thumb that turns red on hover; Firefox gets a thin dark one)

### Consultation form

Fields: full name, email, phone (optional), project location, service, preferred timing, an optional **colour palette**, project details and a consent checkbox. Native validation is on, with focus, hover, invalid and valid states.

The **colour palette** offers 12 swatches (Warm White, Linen, Greige, Taupe, Mist, Soft Grey, Slate, Charcoal, Sage, Sea Blue, Navy, Terracotta) and a pick-your-own colour wheel; a custom pick is matched to the nearest swatch name. It submits two hidden fields: `colour_hex` and `colour_name`.

Submitting currently only swaps the button text to "Thank you". There is no backend (see Known gaps).

### Hero video

The photo behind "Commercial painting." is a background video (`<video class="herovideo">` inside `.hero-img`). Two web versions were made from the original 1920x1080 promo (`assets/Arreaga_video.mp4`, 412 MB, not in git) with ffmpeg: the first 20 seconds, with the black bars and the burned-in logo in the bottom-right cropped away, no audio.

| File | Used for | Size |
|---|---|---|
| `assets/hero.mp4` | screens wider than 800px (1920x766) | 2.9 MB |
| `assets/hero-sm.mp4` | phones and portrait tablets, 800px and below (960x384) | 0.8 MB |
| `assets/hero-poster.jpg` | the still image shown first, and the fallback | 0.2 MB |

A script at the end of `index.html` picks the file, plays it muted, looping and inline (needed for iOS), fades it in once it is actually playing, and pauses it when the hero is off screen. People who prefer reduced motion or have Data Saver on get only the still image, and so does anyone whose device blocks autoplay (for example iOS Low Power Mode). To change the clip, re-encode from the original, for example (ffmpeg): `ffmpeg -ss 0 -t 20 -i assets/Arreaga_video.mp4 -vf "crop=1920:766:0:34" -c:v libx264 -preset slow -crf 28 -pix_fmt yuv420p -r 24 -an -movflags +faststart assets/hero.mp4`, and the same with `,scale=960:-2` and `-crf 29` for `hero-sm.mp4`.

The video is **not** inlined in the single-file builds: `python tools/build.py pages` copies both files into `docs/assets/` next to the published page, while the files in `dist/` show the still poster instead.

### Map

Between the form and the footer, a Google Map embed (`<iframe class="map">`, no API key; it uses the `maps?q=...&output=embed` form) is centred on the business address, **4200 Perimeter Center Dr #245, Oklahoma City, OK 73112**, with an address card and a "Get directions" link that opens Google Maps in a new tab. The card floats at the right of the map on screens wider than 800px and stacks above it on phones. The iframe is `loading="lazy"`, so Google is only contacted when the map nears the screen. To change the address, edit the `q=` value in the iframe `src`, the directions link and the visible address, all in the `#visit` section of `index.html`. The map is the one extra outside request besides Google Fonts, so it needs a connection.

### Accessibility

Visible keyboard focus everywhere, 44px minimum tap targets, 16px form inputs (stops iOS zooming on focus), raised minimum text size, higher text contrast, `prefers-reduced-motion` respected, swatches are keyboard operable with ARIA radio roles.

## The design board

`board.html` shows the site inside real, resizable viewports. Because each frame is an iframe, the site's media queries respond to the frame's width exactly as they would on a device.

| Feature | How |
|---|---|
| Laptop / Mobile / Both | Toolbar toggle. Both shows them side by side |
| Resize any frame | Drag any edge or corner. The opposite edge or corner stays fixed |
| Device snapping | While dragging, dotted rectangles show named devices; the frame snaps when you're within about 10px, and the matched one turns solid red |
| Size menus | Click the size above a frame, or use the toolbar **Size...** menu, to pick a device |
| Zoom | `-` / `%` / `+` buttons, Ctrl or Cmd + scroll wheel or pinch (zooms toward the pointer), Ctrl + `+`, `-`, `0`. Only the frames zoom, not the toolbar or review panel. **Fit** re-fits to the board. Drag empty space to pan |
| Fullscreen | The expand button in the toolbar or on a frame label hides everything but that frame. Esc exits |
| Design review panel | See next section |

Device presets (width x height):

- **Desktop views:** Desktop 1920 (1920x1080), Desktop 1440 (1440x900), Laptop (1280x800), Tablet landscape (1024x768). Desktop frames are limited to 1024-2400px wide.
- **Mobile views:** Surface Duo spanned (1114x720), Tablet (768x1024), Surface Duo (540x720), Large phone (430x932), Phone (390x844), Small phone (360x640). Mobile frames are limited to 280-1200px wide.

Defaults are 1440x900 for Laptop and 390x844 for Mobile. **Reset sizes** restores them.

## Design review workflow

The review panel under the board lets you preview proposed changes live, before they touch the site.

1. Put suggestions in `changes.js` as `window.CHANGES = [ ... ]`. Each item:

   ```js
   { id: 'm-example',            // prefix: v- visual, u- UX, m- motion, f- feature
     tier: 'major',              // 'major' or anything else = minor
     title: 'Short title',
     principle: 'Design principle',
     overlaps: ['other-id'],     // optional: changes touching the same area
     problem: 'What is wrong.',
     fix: 'What the change does.',
     css: '...',                 // injected after style.css
     js: '...' }                 // optional: function body (document, window); may return a cleanup function
   ```

   A `{ summary: true, id, title, problem }` item shows as an overview card. Previews run inside each frame, so JS must use the `window` argument (e.g. `new window.IntersectionObserver`).

2. Reload the board. Each card has a toggle and an **eye** button that scrolls the frames to where the change applies. **Apply all major**, **Apply all** and **Clear** are in the panel header.
3. When happy, ask to apply the selection: the selected CSS is appended to `style.css` (in review order, so later rules win exactly as in the preview), JS blocks go into a script at the end of `index.html`, the round is archived to `changes.archive-*.js`, and `changes.js` is reset to an empty list.

Rounds so far: visual and UX (15 applied), motion (10 applied), colour palette (applied), commercial-first rewrite (declined; the copy stays residential and commercial), industrial commercial look (applied, styling only), bigger header logo (applied). Declined items are kept in the archives.

## Building the shareable files

```bash
python tools/build.py            # all three
python tools/build.py site       # only the website
python tools/build.py board      # only the design board with review panel
python tools/build.py preview    # only the Laptop/Mobile preview
python tools/build.py pages      # only docs/index.html, the file GitHub Pages serves
python tools/build.py all --out some/folder   # everything, written under that folder instead
```

Needs only Python 3 (no packages). Each output is one self-contained HTML file (about 1.3-1.4 MB) with CSS and images inlined. The one outside request is Google Fonts, so type needs a connection.

The two board builds embed the site as a string and give it to their iframes through `srcdoc`. That's why in-page links are handled by script (see gotchas).

`dist/` is generated output and ignored by git. `docs/` is generated too but committed. Rebuild when you want to share or publish; nothing rebuilds automatically after edits.

## Publishing to GitHub Pages

GitHub Pages serves the `docs/` folder of the `main` branch. To publish a change:

```bash
python tools/build.py pages        # regenerates docs/index.html from the source
git add -A
git commit -m "Describe the change"
git push
```

GitHub redeploys in under a minute. Check by loading the URL with a cache-busting query (`?v=2`).

**Authentication:** git on this machine has no stored GitHub credentials. GitHub CLI (`gh`, installed at `C:\Program Files\GitHub CLI\gh.exe`, signed in as `pierregarcia1`) supplies them. If a plain `git push` fails with "Authentication failed", push through the CLI:

```powershell
$env:PATH += ";C:\Program Files\GitHub CLI"
git -c credential.helper= -c "credential.helper=!gh auth git-credential" push
```

Commits use the GitHub no-reply address so the owner's personal email isn't exposed. Pages needs a public repo, so everything in it is visible to anyone, including the source, the design board and the review archives.

## Previewing on an iPhone

Don't send the HTML files as attachments: iOS previews in Mail, Messages and Files typically don't run JavaScript, so the board would appear broken. Open the live link in Safari instead (Share, then Add to Home Screen for an app-style icon). For phone testing use the live site or `arreaga-painting-site.html` rather than the board, since the phone is already the mobile view.

## Implementation notes and gotchas

- **Never put a `<button>` before the submit button inside the form.** The form's inline `onsubmit` edits `this.querySelector('button')`, i.e. the first button. The colour swatches are `<span role="radio">` for this reason.
- **In-page links are handled by script**, not by the browser: inside a `srcdoc` iframe a bare `#about` resolves against the parent page's URL and would reload the whole board inside the frame. The click handler in `index.html` scrolls to the target and closes the mobile menu.
- **The header never changes height on scroll.** Resizing a sticky header changed the page height, which moved the scroll position, which toggled the header again (a visible flicker). It also sits at `top:-1px` with a white 1px top border to avoid a sub-pixel sliver at fractional zoom.
- **Parallax is limited to the hero and About photos** because their containers clip the 12% scale. On photos beside text (project captions, cabinet story) it overlapped neighbouring text.
- **`.menu`, `.call` and nav rules inside the 960px query** use `.header`-scoped selectors so they beat the later review overrides in `style.css`.
- **Reveal effects:** observers watch each image's container, not the image, because a fully clipped image never reports as visible.
- **Scroll anchoring is off** (`overflow-anchor:none`) and `body{overflow-x:clip}` guards against sideways scroll from transformed children.
- The board's frames report sizes in CSS px; at fractional zoom the iframe width can be like 800.5px, which is why the media queries have the `.02` offsets.

## Known gaps

- **Phone number is a placeholder** (`+1 555 010 0000`, a reserved fictional number). Replace it with the real one in both the header phone button and the hero phone link (`href` and the visible text).
- **The consultation form has no backend.** Submit only changes the button text. Wire it to a form service or API; the colour choice will arrive as `colour_hex` and `colour_name`.
- **The hero video and the other new media:** the video plays in the hero but shows other businesses' signage and a worker's shirt with a phone number. The extra files added to `assets/` (a Britton Building photo and two .HEIC photos) are not used on the site yet; .HEIC isn't a web format and needs converting.
- **No real "before" photo** for the cabinet slider (it shows a simulated desaturated copy).
- **No separate pages or links for services and projects.** The service cards and project captions aren't links (their arrows are hidden on purpose), and every call to action goes to the form.
- **Fonts need internet** (Google Fonts). Offline, system fonts are used.
- **Not verified on a physical iPhone or Surface Duo.** Testing so far used browser viewport emulation and the board's frames.
- The `dist/` builds and `docs/index.html` are snapshots; they lag behind the source until `tools/build.py` is run.
